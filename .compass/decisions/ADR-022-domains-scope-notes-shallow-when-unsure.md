# Domain Taxonomy

## Context

[[SPEC-022-vault-organized-per-domain]]: the filesystem is the taxonomy; the folder is the listing and the index has more meaning; complexity grows with depth; reorganization is suggested, and most cases are done behind the scenes when the obvious need arrives; the goal metric is useless tokens loaded per task going to zero. [[RESEARCH-taxonomy-for-unambiguous-placement]]: CS applies classification as delegated namespaces - hop count is the cost unit (B-tree), a folder's marker doc is a RAPTOR-style summary node (answer or descend), generality belongs at the parent and autonomy at the child (DNS, Bazel), names are load-bearing and expensive to change; the human-classification literature supplies scope notes, one-home-plus-facets, shallow-when-unsure, warrant, and the 10-60% filer disagreement every mechanism must tolerate.

## Decision

- **D-01:** One characteristic per level. A folder's name states the value it fixes and reads as the shared subject of everything below it. Siblings are values of one characteristic - orthogonal by construction. A folder factors when the second value arrives: `live-jazz` recordings split into a setting level (live, studio) and a genre level (jazz, rock) the day the first studio-jazz or live-rock item exists, never before. Depth is free; a name widens only when its contents widen. Which characteristic divides first is a judgment call - most stable first - refactored by suggestion when misfit shows. Names are bare finder words, never dumping grounds (`common`, `util`, `misc`), unique among siblings; the same name may recur on other branches (`network/cache`, `gpu-hardware/cache`) and the path identifies it - references to a reused name are path-qualified, and sync's generated links always are. A domain is born from existing documents; a folder past the child ceiling (tunable, 12) draws a `folder_over_ceiling` suggestion from validate and doctor, counted by path so type dirs are covered, scoped to `specs/`, `research/`, and domain folders. Names stay the human's call; grouping moves are suggested, and the obvious ones run behind the scenes.
- **D-02:** A folder's marker doc is named after its folder (`specs/vault-structure/vault-structure.md`) and carries identity and scope only: frontmatter (title, type, status, summary, tags, dates; `type: domain` for a thin domain, `type: spec` for a promoted parent) plus a `## Scope` section - `Class here:` lines, binding `Class elsewhere: X -> [[domain]]` redirects, advisory `See also:` pointers. Basename naming makes every folder link resolve in Obsidian; `vaultlib` recognizes `index.md` alongside it, renamed as folders are touched. The marker doc is the RAPTOR summary node: enough to answer or to descend. `make-domain <type-dir>/<path>` creates folder, marker, and sizing row at any depth, and refuses creation without `--class-here`; validate warns `empty_scope` - a blank promise at the point of doubt is worse than none. Scope notes are authored judgment; nothing regenerates them.
- **D-03:** One physical home per document; tags are the cross-cutting axis; membership elsewhere is a facet or an advisory see-also, never a copy. Filing under doubt stops at the certain ancestor - a wrong deep placement is worse than a shallow correct one - and genuine uncertainty is recorded as `taxonomy_hint:` frontmatter by the authoring agent. Hints drain through two consumers: consolidate's Structure pass takes them as its queue, and validate/checkup surface `taxonomy_hints: N pending` in every vault regardless of caps. A hint clears when acted on - moved, or confirmed where it sits. A type dir under the ceiling has no domains; the root is a small vault's correct home.
- **D-04:** The folder is the listing; no index materializes it. Member listings are read live (`ls`/Glob), `compass tree` is the whole-view with summaries computed at invocation, and the `## Children` convention retires - existing sections are derived listings whose facts live in the filesystem and each child's `summary:`, so they go when their folder is next touched. Two boundaries: the root `index.md` keeps its entry lines as the preloaded boot map, and plain type dirs carry no marker doc of their own. A childless spec stays flat, gaining the folder shape with its first child. Supersedes the listing half of [[SPEC-005-index-auto-maintained-and-mirrored-per-folder]] (read live, not maintained) and amends [[ADR-021-index-speaks-in-domains]] on the marker's content and on `make-domain` as a new command.
- **D-05:** Sync-generated links are vault-relative everywhere, domain lines in the root index included; new links below a domain are written path-qualified; existing bare-stem links stay valid, warned only on real ambiguity. Nested records carry vault-relative names so same-named paths across type dirs cannot cross-contaminate counts. The sync loop guard matches exact root-relative paths - the endswith match silently swallowed every nested marker-doc write, costing sync runs and capture signals.
- **D-06:** The metric is useless tokens loaded per task, driven toward zero; the hot-path cap is only a trigger. No literature instrument measures load-versus-use, so the measure is defined fresh: per task, tokens of vault content brought into context versus tokens whose content the task's output actually used, baselined before the migration and re-measured after. A migration that shrinks the root index but not the useless-token share is not done.

## Consequences

- Filing is a procedure: root domain lines (summaries written as class-here digests, so the obvious case costs no extra read) -> marker doc's Scope on doubt -> shallower if still unsure -> hint if genuinely uncertain. Finding is the same walk downward, one marker doc per hop.
- One write point per change: the file moves, nothing else updates. Nothing can go stale, because nothing but the root map is maintained.
- The type-dir-first shape with domains nested inside is package-by-layer, which the software literature associates with lower cohesion than package-by-feature; the tag-index is the cross-cutting compensation, and the tension is recorded rather than resolved.
- Nothing depends on filers agreeing; the migration's blind drills produce the first LLM-filer consistency datum.
