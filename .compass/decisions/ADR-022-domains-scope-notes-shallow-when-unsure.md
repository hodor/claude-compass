# Domains, Scope Notes, and Shallow-When-Unsure

## Context

[[SPEC-022-vault-organized-per-domain]]: the filesystem is a taxonomy, recursive, every folder with its own index.md (D-05, verbatim), reorganization suggested by the harness rather than remembered by the human (D-07). [[RESEARCH-taxonomy-for-unambiguous-placement]]: filers inherently disagree (10-60%), so unambiguity is engineered - few broad top levels, scope notes at the point of doubt, one primary home with facets as the multi-parent axis, corpus-warranted categories, mechanical split triggers, human-curated tops. A three-lens adversarial review (spec-hygiene, systems, product) found 11 blockers in this ADR's first draft; the decisions below carry those amendments, and the review record lives in [[PLAN-016-domain-taxonomy]].

## Decision

- **D-01:** Few, broad, finder-named domains - a tunable default of 4-6 per type dir to start, never a hard rule (the science says "a handful, not dozens"; no source derives an exact count). Domain names are bare descriptive words a finder would reach for, and they are unique vault-wide: `make-domain` refuses a name any other type dir already uses as a domain, because two areas both named `distribution` re-create on the root surface the exact ambiguity this spec exists to end. Domain names are the human's call at proposal time, always.
- **D-02:** Every domain index carries scope notes, two tiers, in a `## Scope` section: `Class here:` lines naming what belongs, `Class elsewhere:` binding redirects (`X -> [[other-domain]]`), and advisory `See also:` pointers. Scope notes are hand-authored placement judgment; sync never touches them. A domain is never created with an empty Scope: `make-domain` requires `--class-here "<line>"` the same way shape commands require `--reason`, and `validate` warns `empty_scope` on a domain index whose Scope has no Class-here line - an empty promise at the point of doubt is worse than no section.
- **D-03:** One physical home; tags stay the cross axis. No document ever exists in two places. Multi-domain membership is expressed by tags (ADR-004's post-coordinate design, validated by the research) and by advisory see-alsos in scope notes.
- **D-04:** File shallower when unsure. A document that clearly belongs to a domain but ambiguously to its subdomains lives directly in the domain folder; stopping at the certain ancestor is the stated rule in the placement contract. Top-down error propagation makes a wrong deep placement worse than a shallow correct one. A type dir below the ceiling has no domains at all - the root is the correct home for a small vault, and no hint is written where there is nothing to be uncertain about.
- **D-05:** Domains are born from warrant and splits are suggested by ceiling. A domain is created only when existing documents justify it, never speculatively. `compass validate` warns `folder_over_ceiling` when direct children exceed the ceiling (tunable default 12) - counted by path so the type dirs themselves are covered, and scoped to taxonomy-governed dirs only (`specs/`, `research/`, and domain folders; `lessons/` is catalog-indexed and `plans/`, `decisions/`, `handoffs/`, `prs/` are out of scope this round, so they are exempt rather than allowed to become permanent ignored noise). Per SPEC-022 D-07, the warning is a suggestion surfaced to the human every time validate or doctor runs - reorganization is never something the human must remember to trigger, and never automatic.
- **D-06:** Thin domain indexes are `type: domain` - frontmatter: title, type, status (active), summary, tags, created, updated (status included: it is CORE_REQUIRED and its absence is a validate error) - plus the `## Scope` section and the sync-owned Children block. A promoted natural parent stays a folder spec. `compass make-domain <type-dir>/<path>` creates the folder, template (markers included), and sizing-log row, at any nesting depth. This amends ADR-021 in two named places: D-01's fiat that every domain index is "the spec document itself" (the spec template's Problem framing does not fit a topical bag), and D-04's "no new migration machinery" (the thin domain had no creating command: promote needs an existing source file, make-unit is root-only - [[RESEARCH-taxonomy-for-unambiguous-placement]] design Finding 3). ADR-021 is stamped `amended_by` accordingly.
- **D-07:** Sync owns a marker-delimited `## Children` block - the existing section name; no second listing convention is introduced - in every folder's index.md: type-dir indexes (`specs/index.md`, created by sync where absent, satisfying SPEC-022 D-05 for plain folders too), folder-artifact indexes, and unit indexes (retiring make-unit's write-once listing). First level only: each direct child's path-qualified link plus its own `summary:` frontmatter, regenerated between `<!-- children:begin -->`/`<!-- children:end -->` on every sync; everything outside the markers is the author's and untouched, and existing hand-written Children sections are converted into marked blocks once, preserving any authored line that is not a member listing. Sync writes only when the rendered block differs from disk, so a no-change sync touches nothing and neither mtime nor git churns. Folder entry lines' `(folder, N children)` counts refresh in place. No LLM summaries: this revives [[SPEC-005-index-auto-maintained-and-mirrored-per-folder]] minus the held layer - `summary:` frontmatter already exists on every artifact.
- **D-08:** New links to artifacts below a domain are written path-qualified (`[[specs/vault-structure/SPEC-001-name]]`), and sync's own generated links - domain lines in the root index included (`[[specs/vault-structure]]`) - are always the vault-relative form. Existing bare-stem links remain valid: resolution is name-to-path and survives every move, so nothing is backfilled, and validate warns on a bare link only when it is actually ambiguous. The record-name defect underneath (nested non-loose records carry names without their type dir, so same-named domains across type dirs cross-contaminate child counts and Children blocks) is fixed as part of this decision: nested records get vault-relative names.
- **D-09:** `taxonomy_hint:` is frontmatter, written at creation when placement is uncertain (the authoring agent files shallower AND records the hint - it understands the artifact better than any later pass). Two consumers, so the queue drains everywhere: consolidate's Structure pass takes hints as its work queue, and `validate`/`checkup` surface `taxonomy_hints: N pending` as a standing suggestion in every vault, cap breach or not (SPEC-022 D-07). A hint clears when acted on - moved, or confirmed fine where it sits.
- **D-10:** The sync loop guard matches exact root-relative paths (root `index.md`, the meta files, and the sync-generated type-dir indexes), replacing the endswith match that silently swallowed every nested index.md agent-write - a live bug: writing a folder spec's own index today triggers no sync and no capture signal. Because sync may rewrite a folder index the agent recently read (a child write refreshes the parent's Children block), the builder and spec contracts state: re-read a folder index before editing it after any child write.
- **D-11:** Documentation aligns in the same release: obsidian gains the placement contract (D-01..D-04, D-08), scope-note authoring, and the marked-Children convention replacing the hand-maintained instruction; promote-spec's false "CLI refuses" claim is corrected; methodology/setup's "flat, one file each" trees are rewritten; `compass tree` is restored as the whole-tree view (retired unused in ADR-017, and now the direct answer to "the index used to show me everything" - one command renders what the flat index no longer lists).

## Consequences

- The filer's procedure: root index domain lines (hot-path resident, their summaries written as class-here digests so the obvious case costs zero extra reads) -> open the domain index only on doubt -> Scope note answers or redirects -> file shallower if still unsure -> hint if genuinely uncertain. +1 to +2 reads per artifact creation, only on the non-obvious cases.
- Every index, root included, is a first-level view of a real directory; the tree is walkable one hop per level, and `compass tree` shows it whole.
- Nothing depends on filers agreeing: scope notes, facets, and shallow placement all tolerate the measured 10-60% disagreement, and the LLM-filer consistency question stays open by design - the migration's acceptance drills produce its first datum.
- The migration must shrink the root index, not grow it: member lines whose folders now carry them are replaced by domain lines, and the never-destroy audit is "every removed line's content exists in the domain's Children block", not "no lines removed".
